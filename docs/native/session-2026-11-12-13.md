# 2026-11-11 .. 2026-11-13: pacing, text at 720p, shadows, clocks

All numbers are from the real console (handheld), 10 s log windows, same save inside one comparison.

## Frame pacing: `ffns_late_flip` (default on, exact picture)
The game waits each frame for its Swap's flip, which is set from the emulated vertical blank. Blanks came on a fixed
60 Hz grid, so a frame that took 33.4 ms waited for the next blank and became a 50 ms frame (20 fps). Now a Swap that
comes two or more blank periods after the game's last flip gets a blank at once (only while the game flipped in the last
250 ms: loading and menu screens pace another way). Frame-event wait of a late frame 9 ms -> 0.65 ms.

## Audio: `ffns_native_biquad` (default on, bit-exact)
`sub_82A34BB0`, XAudio's per-voice biquad (25-40 % of the mixer thread), as a native body with the state in registers.
The generated code rounds each fmadds twice; the native computes the single fma on the chain and the two-rounding value
beside it and redoes a sample the generated way when they differ. Host check: 11.7 M channel-samples, 0 mismatches.

## Text and HUD at the display's resolution: `ffns_ui_native` (default on; menu "Text and HUD")
The 3D image stays at the render resolution (612 lines by default). After the game's composite pass the image is scaled
once into a 1280x720 target and the HUD, text and the front-buffer resolve use that. Frames without a composite (2D
screens) have two parts: the surface that goes to the front buffer, and since 2026-11-13 the layer the screen is drawn
into first (the first other whole-screen colour surface drawn or cleared with no depth buffer bound). Before that the
layer was drawn at 612 lines and scaled twice: thin strokes of the font broke up. Checked against a true 720p run.

## Shadows on the field: `banjo_deko3d_depth_handover` off
A depth resolve that needs no words was not drawn; the texture took the target's image at the next clear. On the field
the two shadow maps were handed over a few seconds after the player moved and were then sampled stale: every shadow
vanished or stood in the wrong place (battles were not affected). The 10 s line "depth hand-over ... N resolves not
drawn" shows ~2 a frame when it happens. Off by default now; its GPU saving in this game was not measured.

## Clocks (options menu, off by default, no sys-clk)
CPU 1020 (stock) / 1224 / 1428 / 1581 / 1785 MHz (`ffns_cpu_mhz`), GPU 460 (stock) / 537 MHz (`ffns_gpu_mhz`), set
through one shared clkrst session a clock and put back at exit. Three sessions at most: the earlier six ran `pcv` out of
session memory beside other clock tools (Atmosphere fatal 2011-0102).

## Options menu
Saved choices are written in front of the first TOML table of `ffxiii2.toml`; a copy of a key inside a table is removed.
(They were appended at the end, inside `[input_p1]`, and ignored at the next start.) The FPS counter line is gone.

## Measurements
| view | clocks | result |
|---|---|---|
| New Bodhum heavy view, standing (410-450 draws) | CPU 1428 / GPU 460 | 28.9 fps mean of 6 runs; main thread 93 % busy |
| opening cutscene, heavy phase (400-450 draws) | CPU 1581 / GPU 537 | 25.8-28.5 fps; main thread 91 % busy (waits ~12 %) |
| New Bodhum beach at night, running | CPU 1581 / GPU 537 | 26-29.5 fps (GPU 27-30 ms) |
| same place, standing | CPU 1581 / GPU 537 | 29.75-30.02 fps (GPU 22-23 ms) |
Stable 30 fps is not reached in the heavy views: they are bound by the game's main thread.
